    About IQ Captures

    What is it? An IQ capture is a recording of the raw complex baseband samples coming out of the SDR — the same in-phase / quadrature pairs the demodulator sees, one per sample at the receiver's sample rate. Each "Capture IQ" button below grabs the number of seconds selected in the Capture duration picker (default 1 s, up to 60 s) and saves them as a complex64 NumPy file (.npy). At a typical FM rate of 250 kHz a 1-second capture is around 2 MB; a 30-second capture is about 60 MB.

    What is it for? Captures let you investigate problems off the air — i.e. with the exact bits the radio was receiving, replayable as many times as you like. Typical reasons to grab one:

    • RBDS / RDS decode issues on an FM receiver — feed the file into scripts/rbds_diagnose.py to step through pre-sync, block CRCs, group decoding and burst-FEC repairs without disturbing the live receiver.
    • SAME / EAS demod investigations — capture a known-bad alert audio path and replay it through the demodulator with different settings.
    • Signal-quality questions — load the capture into inspectrum, GNU Radio, MATLAB, or a custom Python script to look at spectrum, modulation, SNR over time, interference, etc.
    • Sharing evidence in a bug report — attach the .npy so a reviewer can reproduce the exact decoder behaviour you saw.

    What do I do with the file after downloading?

    1. Save the .npy somewhere persistent — captures are single-use on the server (the file is deleted immediately after the download finishes).
    2. Load it in Python: 
      import numpy as np
iq = np.load("iq_WXTEST_250000Hz_....npy")  # complex64 array
print(iq.shape, iq.dtype)
      The filename embeds the receiver identifier and sample rate, e.g. iq_<id>_<rate>Hz_<timestamp>_<cmd>.npy.
    3. For RBDS troubleshooting, run: 
      python scripts/rbds_diagnose.py path/to/capture.npy
      The script consumes the file at the rate encoded in its filename and prints a block-by-block report.
    4. For visual analysis, open the file with inspectrum or import it into GNU Radio via a File Source block (set "Output type" to complex).

    Captures are stored under /var/log/eas-station/captures on the server (override with the RADIO_CAPTURE_DIR environment variable). Each download URL is a one-time, hex-UUID link that expires after 10 minutes.

    Troubleshooting Tips

    Cause: Receivers are configured in the database but not loaded into RadioManager.

    Solution: Restart the web application:

    sudo systemctl restart eas-station.target webapp
# or
sudo systemctl restart eas-station

    Possible causes:

    • Antenna not connected or disconnected
    • Wrong frequency for your location
    • Signal too weak
    • SDR device issue

    Solution: Check antenna connection, verify frequency settings, and test with a known-good frequency (e.g., local FM station).

    Possible causes:

    • Receiver just started (wait a few seconds)
    • Sample buffer not initialized
    • SDR device communication issue

    Solution: Wait 5-10 seconds and refresh. If problem persists, restart the receiver from the main settings page.

    Checklist:

    • Check that "Loaded Instances" matches "Database Receivers" above
    • Verify "With Sample Data" is greater than 0
    • Open browser console (F12) and check for JavaScript errors
    • Verify auto-refresh checkbox is enabled on /admin/radio page
    • Test the spectrum endpoint directly: /api/radio/spectrum/1
